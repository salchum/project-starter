# REQUIRED task or release — user follow-up summary

- Accountable PM / timestamp / policy SHA: REQUIRED
- Delivered outcome / acceptance criteria met: REQUIRED
- Candidate SHA(s) / intended environment, if applicable: REQUIRED
- Review and audit record links / verdict / exact scope and SHA for each: REQUIRED
- Test plan/version / tester report / mandatory coverage / unresolved defects: REQUIRED (or not applicable with reason)
- Missing, interrupted or outdated reviews/checks: REQUIRED (or none)
- Findings resolved / open / risk accepted, with source finding IDs: REQUIRED
- Residual risks and explicit human acceptance evidence: REQUIRED (or none)
- Follow-up actions: REQUIRED (or none)
  - For each: priority, source finding IDs, action owner, next action and dependency.
- Decisions required from the user: REQUIRED (or none)
  - For each: concrete decision, recommendation and consequence of waiting.
- Readiness / commit / integration / push / staging / production status: REQUIRED (or not applicable)

Link the underlying evidence rather than repeating full reports. Preserve
disagreements and blocked results; do not convert incomplete evidence into PASS.
Keep review acceptance, release readiness and deployment authorization separate.
